The brief for every Claude Code session on this repo. README.md holds the pre-registration; if the

## The project

Lexsi AI Safety and Alignment Hackathon, Track 2b, problem statement 6 ("Repairing safety drift
without retraining"). CAST also covers statement 8 (inference-time steering), and the
multilingual angle covers 2a statement 4. The official deadline is Nov 14 23:59 AoE (Nov 15 11:59
UK). We submit on Nov 13 and treat Nov 14 23:59 UK as the hard stop.

We take one useful Hindi LoRA adapter of Tiny Aya Global (CohereLabs/tiny-aya-global, 3.35B) and
run a retain / repair / reject acceptance test. Does the adapter drift on safety, in Hindi and in
other languages? Which cheap post-hoc repair restores safety while keeping the adapter's gain and
not over-refusing? Every repair is measured against simply scaling the adapter down.

- Repairs: WiSE-FT attenuation (the baseline), ReSta-A (add alpha times Global minus Base), and
  CAST (conditional activation steering, one global threshold).
- Diagnosis (harm probes, refusal direction, ablation) is exploratory and never blocks CAST.
- The pipeline chains three Lexsi tools: CuratorKIT for data, SafeTune for the repairs and the
  direction tools, and AuditKIT as the evaluation record.
- Languages: en and hi are primary. zh and es are transfer languages, validated natively. ar and
  th are exploratory.

## Rules that are never broken

1. **Dev vs final.** Every sweep, threshold, layer choice and selection uses train, fit or dev
   prompts. The final split is touched only by the final eval of frozen variants. Splits are by
   pid, identical in every language, committed in `data/splits/`, never recomputed.
2. **One code path.** Every variant (stock, adapters, repairs) is built by
   `lift.models.variants.build_variant` and generated by `lift.models.generate`. No side script
   produces a reported number.
3. **Every prompt stays in the denominator.** Judge failures, empty outputs and OOM retries are
   recorded and counted (as unclear where needed), never dropped.
4. **Cache keys** come from `lift.cachekey.generation_key`. Never reuse an output across
   interventions, and never hand-edit outputs.
5. **Locked decisions** (README pre-registration, `configs/*.yaml`) change only with a dated
   entry and a reason in `docs/decisions.md`. No new experimental arms.
6. **Harmful content stays out of public view.** During the build, raw generations, judge logs
   and unrepaired adapters live only in `outputs/` (gitignored) and the private HF runs repo
   (`LIFT_RUNS_REPO`). At submission the rules require every artifact to be hosted on HF, so
   adapters and raw logs go up as gated repos (manual approval for raw harmful completions);
   everything else is public. Never put a harmful completion in a commit, PR, issue, printed log
   or summary. Quote at most ~10 words, then `[redacted]`.
7. **Tests run offline on CPU.** `pytest` (which skips the `gpu` and `net` markers by default)
   passes on every commit. Model code is tested on a tiny randomly initialised cohere2 model
   built from a config (fixture `tiny_cohere2` in `tests/conftest.py`, marker `torch`), never by
   downloading Tiny Aya.
8. **Commits:** small, with plain descriptive messages and no Co-Authored-By or Claude-Session
   lines. Work on the branch your prompt names and open a PR to `main`.
9. **Don't hide results.** If a gate fails or a number looks wrong, stop and report it. Don't
   tune around it.

## Data contracts

Records are defined in `lift/schemas.py`: PromptRecord, VariantSpec, GenerationRecord,
JudgementRecord, UtilityVerdict and HumanLabel. Every JSONL line is one record, written with
`lift.io`. The pid is shared across languages: `prh-test-0042` is the same harmful prompt in all
six languages, so pairing, splitting and clustering all go by pid.

- Prompts: `data/prompts/{set}_{lang}.jsonl`
- Generations: `outputs/generations/{variant}/{set}_{lang}_{split}.jsonl`
- Judgements: `outputs/judgements/{judge}/{variant}/{set}_{lang}_{split}.jsonl`
- Run manifests (cost section): `outputs/manifests/*.json`

## Environment

- **Python and install.** SafeTune needs Python 3.12. Install everything with
  `pip install -e ".[gpu,data,eval,report,dev]"`; the core needs only numpy, scipy, pyyaml and
  pydantic.
- **Where GPU runs happen.**
  - **Primary: Colab A100, bf16.** The Google AI Pro plan gives 200 compute units a month.
    Jobs are launched with the Colab CLI (`google-colab-cli`, command `colab`) from a local
    Claude Code session (`colab/README.md`), or from a notebook if the CLI misbehaves.
  - **Backup: Kaggle T4 x2, fp16** (`kaggle/README.md`). A T4 x2 is two separate 16 GB devices:
    the generator goes on `cuda:0` and the judge on `cuda:1`. On a single GPU, both share it.
  - A GPU job runs a git ref (`lift remote --ref`, Kaggle `BRANCH`), not the working tree, and
    installs with `-c constraints.txt`. The ref needs P01 and P02 (P02 alone has P01's prompt
    loader and LangID as stubs).
- **One precision for every reported number.** Every reported generation uses bf16. A T4 fp16
  run can count only if Gate 0's fp16-vs-bf16 check passes. Paired comparisons never mix
  precisions: the cache key includes the dtype, `lift.judge.pipeline.load_labels` refuses a cell
  in another dtype, and every paired comparison loads its two sides with
  `lift.judge.pipeline.paired_labels`, which refuses mismatched dtypes, judges, models, chat
  templates or decoding settings. An fp16 cell is read only while `outputs/metrics/gate0-fp16.json`
  (at least 200 prompts compared) and the bf16 `gate0.json` it compared against both pass for its
  Global revision, and only if it was made (and judged) under the comparison's harness, decoding
  and GPU class (`check_dtype_licence`). fp16 runs are refused on a GPU with native bf16.
- **Claude Code sessions** run in the Claude desktop app on a Windows laptop (PowerShell). They
  have no usable GPU for this project.
  - Write cross-platform Python: `pathlib` everywhere, and files written with `newline="\n"`
    (`lift.io` already does this).
  - Only the Linux GPU runtimes get shell scripts, never local steps.
  - Write the code and offline tests, then either launch the job yourself with the Colab CLI
    (when it is installed and logged in) or end with the exact commands for the human, in
    PowerShell syntax for local steps.
- **Sessions are wiped.** Colab and Kaggle sessions lose their disk when they end (Kaggle after
  12 h). Every job pulls from and pushes to the runs repo (`lift sync`), and resumes by cache
  key. One file never holds two stacks (torch, transformers, GPU class): a finished cell is reused
  on any stack, but an unfinished one resumes only on the stack that started it, or is made again
  with the `lift restart` line its refusal prints (a job line right after `lift sync pull`).
  `lift generate`, `judge` and `run-dev` exit 3 when they finished but skipped cells (each listed
  with its remedy); the runners go on with the next line.
- **Secrets.** `HF_TOKEN` (with accepted access to tiny-aya-global and tiny-aya-base),
  `GITHUB_TOKEN` (remote runtimes clone this private repo), the judge API key with its spend cap
  `LIFT_JUDGE_MAX_USD` (per lift process), `LIFT_RUNS_REPO`, and `GOOGLE_TRANSLATE_API_KEY` (the
  Cloud Translation API, only for `lift data build` runs that translate). Set them with a hidden
  prompt, never typed or pasted on a command line or into a chat.
- **Pinned revisions.** `lift generate`, `lift judge` and `lift run-dev` refuse a revision that is
  not a commit sha; Gate 0 (`lift smoke`) resolves and prints the shas to pin. Pin them in
  configs/project.yaml with a dated decisions.md entry, then commit and push to the ref the GPU
  job runs.

## Tiny Aya

- **Architecture.** cohere2 / Cohere2ForCausalLM. 36 decoder layers at `model.model.layers`,
  d_model 2048, 16 query and 4 KV heads, a 262,144-token vocabulary and tied embeddings. Blocks
  run attention and MLP in parallel, and attention alternates sliding-window and global layers
  3:1.
- **Weights and precision.** Weights are bf16 (~6.7 GB, gated, CC-BY-NC-4.0 plus Cohere's
  acceptable-use policy). A100 and L4 run bf16 natively. T4s have no bf16, so they load fp16,
  and Gate 0 checks fp16 against bf16 on 200 prompts before any T4 number counts.
- **Chat template.** The template always injects a ~366-token default "contextual safety mode"
  preamble. It stays on for training and evaluation. The only exception is the preamble on/off
  diagnosis.
- **Sequence length.** Never set the training length below 512 tokens. The preamble eats a third
  of 1,024.
- **Base model.** tiny-aya-base has no chat template. It is loaded only as the ReSta reference.
- **Revisions.** Record model revisions as commit shas. `lift.cachekey` refuses `main`.
- **Steering layer.** SafeTune's notes put the refusal-steering layer near 24 of 36, and say
  ReSta at alpha 1 breaks the model.

## Toolkits (verified against source, Nov 3; details in docs/toolkit-notes.md)

- **SafeTune 0.1.12 (pinned).**
  - `apply_wise_ft(model, aligned, alpha)` computes `alpha*aligned + (1-alpha)*model`. Its alpha
    points TOWARD stock, so our lambda maps to `alpha = 1 - lambda`.
  - `apply_resta(ft, *, base, aligned, alpha, dare=False, device="cpu")` streams one tensor at a
    time and mutates in place. Pass `dare=False` explicitly.
  - `fit_cast_condition(...)` and `CASTModel(model, vectors, condition=..., alpha=...)` fit on
    chat-formatted prompts by default, and the gate decides per prompt. `with cast:` gives the
    gate always on.
  - `extract_refusal_direction(..., RefusalDirectionConfig(pick_layer=L))`. Always force the
    layer: the built-in sweep scores refusal with English substrings.
  - `extract_caa_vectors(...)` produces the steering vectors.
  - Only use entry points badged Faithful in `docs/reference/feature-map.md`, not
    ReStaTrainer or RefusalDirectionTrainer.
  - On Kaggle/Colab, `pip uninstall -y torchao` if SafeTune imports fail.
- **CuratorKIT 0.1.22.** The no-API path is `Curator(CuratorConfig(dataset=..., dedup="minhash",
  clean=True, export_formats=["messages"], output_dir=...)).run()`. The format is `messages`
  (it writes `sft_messages.jsonl`); an unknown format only warns and exports nothing. Keep its
  manifest.json, rejected.jsonl and lexsi_provenance.json, and don't run its English toxicity
  gate on Hindi.
- **AuditKIT 1.1.3.** `auditkit.evaluate(dataset: list[Sample], model, scorers=[...],
  config=RunConfig(...), tags=[...])`; `lift.audit` uses the precomputed path with custom metrics
  and patches out its disk cache (docs/toolkit-notes.md). Its WinRate/Elo metrics are reference-
  or overlap-based, not judge-based. Never use its `paired_bootstrap`: it resamples uncentred
  differences and returns no intervals. `lift.stats` replaces it.

## PolyRefuse (mainlp/Multilingual-Refusal)

- **Test files.** `harmful_test_translated_{lang}` (572 rows) and `harmless_test_translated_{lang}`
  (500 rows) have `instruction` = the ENGLISH source and `instruction_translated` = the target
  text. The en harmful file has only `instruction`. Rows align by index across languages.
- **Train and val files.** `*_{train,val}_translated_{lang}` have `instruction` = the TRANSLATED
  text and no English field. Their English sources are in `dataset/splits/`, row for row, except
  zh harmless train and val: they are a different draw that lines up with no English file
  (`sources.polyrefuse.misaligned`, docs/decisions.md).
- **Missing sets.** There is no Hindi anywhere and no zh harmless test. The translation job
  makes them, and zh harmless train from its English source, with Google Translate, the tool
  PolyRefuse itself used, reached through the Cloud Translation API (engine `google_cloud`,
  records `google-cloud-v2`; decisions item 48: the web endpoint refused the laptop and Colab).
  Harmless val is unused.
