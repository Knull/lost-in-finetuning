# Lost in Fine-Tuning: Hindi training sets

The Hindi instruction rows that the LoRA adapters of this study were trained on, with the files
CuratorKIT wrote when it curated them. The study is a retain / repair / reject test of a Hindi adapter
of Tiny Aya Global (Lexsi AI Safety and Alignment Hackathon, Track 2b, statement 6). Its pipeline
chains three Lexsi tools: CuratorKIT builds these training sets, SafeTune applies the repairs, and
AuditKIT records the evaluation. Code and pre-registration: {{ github }}. Labels, result tables and
run manifests: {{ logs_repo }}.

Every row here is training data taken from a public dataset. None is a model output: nothing in this
dataset was generated by Tiny Aya or by an adapter.

## The training sets

{{ table }}

- `aya/dedup`: Hindi rows of the Aya Dataset, deduplicated. The standard recipe trains on it.
- `indicalign/dedup`: a sample of the Hindi rows of IndicAlign's `Dolly_T` subset, deduplicated. The
  standard recipe trains on it.
- `indicalign/raw`: a sample of the same rows without deduplication. Only the stress recipe trains on
  it. That recipe is a stress test, used so that the repairs have a safety drift to work on. It is not
  a recommended way to train.

{{ published }} Every run recorded the sha256 of its training file in its manifest (`data_sha256`
in `manifests/train-*.json` of the logs dataset), and the publishing code stages a set only while its
training file has that sha256 and every registered adapter has such a run. "Rows trained" is lower
than "Rows in the training file" where a row's prompt, with the model's default preamble, alone
reached the training length and left no answer token to learn from. Those rows were dropped, and
each manifest lists their ids (`dropped_unfit`).

{{ withheld }}## How they were made

1. `lift data build` loads the Hindi rows of each source at a pinned revision (below) and cleans
   them. It keeps a row only if its instruction and its answer both read as Hindi and the answer
   does not repeat itself, drops the IndicAlign rows whose Dolly original came with a context passage
   (IndicAlign left the passage out), and takes out the held-out utility prompts of the study and
   every near-duplicate of one.
2. CuratorKIT {{ curatorkit }} curates each pool on its no-API path: a schema gate on length, exact
   then MinHash deduplication, cleaning, and the `messages` export. The stress recipe's set skips
   deduplication.
3. Each training file is a sample of the curated rows, chosen by a hash of the seed and the row id
   (all of them where fewer than the target remain) and written in id order.

## Files

One folder per training set, at the path it has under `data/sft/` in the code repository, which is
the path every training run recorded (`data_path`):

- `{set}/sft_messages.jsonl`: the training rows, less any row listed under "Withheld rows", one
  JSON object per line with an `id` and `messages`: one user turn and one assistant turn.
- `{set}/curatorkit/manifest.json`, `rejected.jsonl` and `lexsi_provenance.json`: CuratorKIT's own
  files for the run that curated the set: its stage counts and versions, the rows it rejected, each
  with the reason, and its provenance record. They are the files of the last build. The sets were
  built once more after the first adapters had trained, and that build gave the same rows and the
  same sha256 as the files those adapters had read (`docs/decisions.md` item 67 in the code
  repository), so CuratorKIT's timestamp can be later than a training run's.
- `{set}/curatorkit/curatorkit_summary.json`: our summary of that run, with the ids of the rows
  rejected and of the rows removed as duplicates.
- `{set}/selection.json`: the ids sampled into the training file, the counts, the seed, the training
  file's sha256 and the rules the build applied.
- `report.json`: every count of the build for the three sets, from the rows loaded to the rows
  sampled.

## Limitations

The IndicAlign rows are machine translations (IndicTrans2) of English instructions and answers.
The rows of both sources were selected by the automatic rules above, not reviewed one by one. The
sets were built to train the adapters of this study, not as a benchmark or a recommended Hindi
training set.
